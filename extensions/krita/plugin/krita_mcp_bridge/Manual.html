Krita MCP Bridge

Runs a small HTTP listener on 127.0.0.1 only, protected by a random bearer token minted per Krita session into ~/.krita-mcp/bridge.token. The krita-mcp server (a dangler fleet extension) reads that token and the port from ~/.krita-mcp/bridge.json and turns MCP tool calls into libkis calls on Krita's GUI thread.

Every request runs with a deadline: if Krita is showing a modal dialog or is busy, the caller gets a krita_busy error instead of hanging.

Log: ~/.krita-mcp/bridge.log. Optional switches (files in ~/.krita-mcp): allow_exec enables arbitrary Python (run_python), any_action lifts the QAction allow-list. Both are off by default.
